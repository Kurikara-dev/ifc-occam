# ユーザーテストガイド (IFC簡略化ワークベンチ)

このドキュメントは、開発者ではない方が本ツールを実際に触って動作確認するための
手引きです。画面の刷新(サイドバーのタブ化・
ファイルダイアログ化・ステージ表示など)に合わせて全面的に書き直しました。

## 1. 起動方法

1. `start.bat` をダブルクリックしてください。
   - 黒いウィンドウ(コマンドプロンプト)が開き、しばらくするとブラウザが自動で
     開きます。開かない場合は、黒いウィンドウに表示された URL を開いてください。
   - PyInstaller版のexe配布物がある場合は `start-exe.bat` でも同じ画面が開きます
     (Python環境が無い端末向け)。dist フォルダが無い場合は分かりやすいエラー
     メッセージが出ます。
2. 黒いウィンドウは起動中サーバの画面です。**テスト中は閉じないでください。**
   終了したいときはこのウィンドウで `Ctrl+C` を押すか、ウィンドウを閉じてください。

### ポートが使用中の場合

他のアプリが既にポートを使用している場合、自動でポート番号を変えて起動します
(既定は8000番から順に空きポートを探します)。実際に使われているポート番号は
黒いウィンドウに表示される URL で確認してください。

## 2. 対象ファイルについて

このガイドを試すには、**手元にある任意の `.ifc` ファイルを1つ用意してください。**
以下では、そのファイルを「対象ファイル」と呼びます。

対象ファイルは、`start.bat` を起動したフォルダ(このフォルダ)の中、または
その中のサブフォルダに置いてください。次章で説明する「ファイル指定」ダイアログは
**サーバを起動したフォルダの外を見ることができません**(セキュリティ上の
仕様です)。別の場所にあるファイルを試したい場合は、そのファイルをこのフォルダの
中にコピーするか、そのファイルがあるフォルダで `start.bat`(または
`python -m ifc_occam serve`)を起動し直してください。

ファイルサイズが数百MBを超える場合、読込に数十秒〜数分かかることがあります。
「ファイル指定」でファイルを選んだ直後に、画面へ読込時間とメモリ使用量の目安が
表示されるので、それを見てから読込を始めるかどうか判断できます。極端に大きい
ファイルの場合は、GUIではなくCUI版での診断を勧める案内が自動で表示されます
(CUI版については「7. CUI版」を参照してください)。

## 3. 推奨シナリオ

以下の順で触っていただくと、主要機能を一通り確認できます。

### ① ファイルを選んで読み込む

1. 画面左上の「ファイル指定」ボタンを押します。サーバを起動したフォルダを起点に
   した、ファイル一覧のダイアログが開きます。
2. フォルダは名前をダブルクリックすると中へ移動します。ダイアログ上部のパンくず
   (「(ルート)」から始まる表示)をクリックすると、そのフォルダまで一気に
   戻れます。
3. 対象ファイル(`.ifc` のみが一覧に出ます)をクリックして選び、「選択」ボタンを
   押します。
4. 選択すると、「読込」ボタンの下に **推定読込時間** と **推定メモリ使用量** が
   表示されます(実測2点から算出した目安であり、実行環境によって前後します)。
   ファイルが極端に大きい場合は、この下に警告色で
   `python -m ifc_occam cui "<対象ファイル>" --scan-only` という案内が追加表示
   されます。
5. 「読込」ボタンを押すと読込が始まります。読込中は経過秒が表示されます。
   完了すると、サイドバー上部の一覧タブ(クラス/レイヤー/重複形状)に診断結果が
   入ります。

補足: 「パスを直接入力」という折りたたみ欄も用意されています。サーバ起動フォルダ
からの相対パスが分かっている場合は、ダイアログを使わずここへ直接入力してもかまい
ません。

### ② 一覧タブとクイック操作

1. サイドバー上部のタブは「クラス」「レイヤー」「重複形状」の3種類です。
   タブのラベルには件数が出ます(例: `クラス 25`)。件数が0件のタブは押せません
   (対象ファイルにレイヤー情報が無い場合、レイヤータブはこの状態になります。
   不具合ではなく仕様です)。
2. 重複形状タブは、節約可能な三角形数が多い順に上位50件までしか表示しません。
   全体がそれを超える場合は、一覧の下に件数の注記が出ます。
3. 一覧の行をクリックすると、その行(そのクラス/レイヤー/重複形状グループ)の
   全要素が選択されます(既存の選択は置き換わります)。`Shift` を押しながら
   クリックすると選択に追加、`Ctrl`(Macでは `Cmd`)を押しながらクリックすると
   選択から除外されます。この操作方法は一覧の上に常時ヒントとして表示されて
   います。
4. 行にマウスを乗せる(またはキーボードで行内にフォーカスする)と、右端に
   「削除」「軽量化」「残す」の3つのクイックボタンが現れます。押すとその行の
   全要素を対象に即座にその操作が行われます(「削除」は確認モーダルを経由
   します。中身は次の③で説明します)。

### ③ 3Dビューでの選択・操作・解除

3Dビューのマウス操作の割り当ては次の通りです。

| 操作 | 割り当て |
|---|---|
| 回転 | 右ドラッグ(カーソル直下の部材を軸に回ります) |
| 見回し(カメラは動かず、首を振るように視線の向きだけ変わります。右へドラッグすると右を向きます) | 左ドラッグ |
| 平行移動(パン) | ホイールボタンのドラッグ |
| 拡大縮小 | ホイールスクロール |
| 選択 | 左クリック(動かさずに押して離す) |

右ドラッグ中はブラウザの右クリックメニューは出ません(仕様です)。

1. 3Dビュー上の要素を直接クリックすると、その要素だけが選択にトグルされます
   (すでに選択中の要素をクリックすると、その要素だけ解除されます)。
2. 何か1件以上選択すると、選択していない要素は暗く表示され、選択した要素には
   黄色い縁取りが付きます。選択が非常に大きい場合は縁取りの生成だけが省略され、
   その旨が選択チップの横に表示されます(黙って何も起きないわけではありません)。
3. 選択している状態で画面下部の操作バー(常に表示されています)の「削除」
   「軽量化」「残す」のいずれかを押すと、操作リストに1件積まれます。
   - 「削除」は確認モーダルが出ます。直接削除される件数と、連鎖して一緒に消える
     件数(開口部に付随する窓など)が表示されるので、内容を確認してから確定して
     ください。
   - 「軽量化」は手法(bbox/凸包/間引き)を選ぶと、その手法が何をするかの説明文
     と、選択中の要素に対する効果の目安(三角形数がどれだけ減るか)が表示されます
     (凸包は事前に正確な数値を出せないため、目安は表示されません)。
4. 選択を解除する方法は次の4つです。どれを使ってもかまいません。
   - `Esc` キーを押す(全解除)
   - 3Dビューの何もない場所をクリックする(床の上をクリックした場合も
     「何もない場所」として扱われます)
   - 選択済みの要素をもう一度クリックする(その要素だけ解除)
   - 操作バー左端の選択チップ(`選択中 N件`)の「×」を押す(全解除)

補足: 3Dビュー右上の「配色」セレクトでは、モデルの色の決め方を「IFCの色」
(部材がIFC上で持っている元の色をそのまま表示)と「クラス別」(IFCクラスごとに
自動で割り当てた色で塗り分け)から選べます(既定はIFCの色)。切り替えるとその場で
塗り直されます。元の色を持たない要素はグレー(無彩色)で表示されます。

補足: 3Dビュー右上の「ステージ」ボタンで、床・グリッド・軸の表示/非表示を
切り替えられます(既定は表示)。また、サイドバーとビューの境界をドラッグすると
サイドバー幅を変えられ、左上の「«」ボタンで折りたたむと3Dビューを広く使えます。

補足: 3Dビューの座標系はIFCの仕様(+Zが上)をそのまま使っています。軸の表示
(上記のステージに含まれます)で上を向いている青い線がIFCの+Z軸です。

### ④ 操作パターン(旧: プリセット)

1. 操作バー内の「操作パターン」欄では、それまでに積んだ操作をまとめて名前を
   付けて保存できます。「現在の操作から保存」ボタンを押すと、保存用
   のモーダルが開きます。
2. **保存できるのは、あるクラスまたはあるレイヤーの全要素にぴたり一致する操作
   だけです。** 部分選択(一覧の一部だけを選んで行った操作)は保存できないため、
   モーダルに `保存対象: N件 / 保存できない操作: M件(部分選択のため)` という
   形で対象外の件数が明示されます。M が0件でなくても、N が1件以上あれば保存は
   続行できます。
3. 「サンプルを追加」ボタンを押すと、あらかじめ用意されたサンプルの操作パターン
   が一覧に追加されます(既存の操作パターンは消えません。サンプルと同じ名前の
   ものがすでにある場合だけ、その1件が上書きされます)。
4. 保存した操作パターンの「適用」を押すと、ルールごとの対象件数を確認する
   モーダルが出ます。内容を見てから確定するかどうかを判断してください。「×」で
   その操作パターンを削除できます(削除も確認モーダルを経由します)。

### ⑤ 出力する

1. 操作バー下部の「保存先を指定」ボタンを押すと保存ダイアログが開きます。既定の
   ファイル名は `<対象ファイルの名前>_light.ifc` です。
2. **読込中のファイルと同じ名前は選べません。** ダイアログの一覧では該当する
   行が選択不可になり `(読込中のファイル)` と注記されます。手打ち欄に直接
   入力した場合も、赤字の警告(`出力先が読込中のファイルと同じです。別の名前に
   してください。`)が出て出力ボタンが押せなくなります。
3. すでに存在するファイル名を指定した場合は、`{ファイル名} は既に存在します。
   上書きしますか?` という上書き確認のモーダルが出ます。
4. (任意)「省メモリ方式で書き出す(逐次ゴミ回収)」にチェックを入れると、
   書き出し時のゴミ回収を逐次方式に切り替えます。既定(チェックなし)は
   一括GCで、出力先の隣に一時ファイルを作りメモリを多めに使う代わりに
   速い方式です。チェックはメモリが足りずに出力が失敗する場合の退避手段です。
   生き残る要素と幾何はどちらの方式でも同一で、同じ入力・同じ操作であれば
   出力は一括GCと完全に一致します(共有形状化=consolidateがOFF(既定)の場合。
   consolidateは共有先の代表を非決定的な順序で選ぶためONだと両方式の出力は
   等価ですがバイト一致はしません。以前は逐次方式が使われなくなった旧形状の
   断片を残し出力が数%大きくなることがありましたが、この差は解消済みです。
   CUIの `--inline-cleanup` と同じです)。なお、ファイル指定時に表示される
   「推定メモリ」は読込時の推定であり、このチェックでは変わりません。
5. 「出力」ボタンを押すと出力が始まります。出力中は経過秒が表示されます。
   完了すると、削除/軽量化/スキップの件数、出力先のパス、処理ステージ別
   (開く/削除/簡略化/重複再抽出/重複統合/書き込み)の所要秒数が表示されます。
   何らかの理由で出力に失敗した場合は、`出力に失敗しました: <理由>` という
   形で理由が画面に表示されます。

## 4. 受け入れチェックリスト

出力したIFCファイルをRebro Viewerで開き、以下を確認してください。

- [ ] **Rebroで開ける**(エラーで開けない・スキーマエラーが出ない)
- [ ] **表示破綻なし**(モデルが欠けたり、形状が変形したりしていない)
- [ ] **選択応答が実用的**(クリックで要素を選ぶ操作が、待たされる感じなく
      反応する)
- [ ] **削除連鎖の妥当性**(削除したクラスの要素だけでなく、削除に伴って
      一緒に消えるはずの部材(開口部に付随する窓など)も正しく消えている。
      逆に、消すつもりのなかった要素が誤って消えていない)
- [ ] **寸法が正しい**(モデルの見た目の大きさが元モデルと一致している。
      1000倍に拡大されたり、1/1000に縮小されたりしていないか。単位バグの
      再発検知として特に重要です)
- [ ] **色が保持されている**(元モデルの部材ごとの色が出力後も維持されている)
- [ ] **削除した要素が消えている**(操作で削除指定した要素が、Rebro上に
      実際に存在しない)

これらのいずれかで問題が見つかった場合は、どのシナリオ・どの操作で発生したか
をメモして開発側にフィードバックしてください。

## 5. 既知の制約

- **読込時間はファイルサイズにおおよそ比例します。** 「ファイル指定」でファイルを
  選んだ直後に画面へ表示される推定時間(実測2点から算出した目安)を参考にして
  ください。目安としては、20MB程度なら1分前後、100MB程度なら1〜2分程度です。
  途中で画面がフリーズしたように見えても、読込中である可能性が高いです。
  焦らず完了までお待ちください。
- **出力(エクスポート)は削除件数が多い場合、数分かかることがあります。**
  削除件数が少ない、または簡略化(bbox化等)のみの場合はもっと短時間で完了
  します。完了後に表示されるステージ別秒数(開く/削除/簡略化/重複再抽出/
  重複統合/書き込み)を見ると、どの処理に時間がかかったかが分かります。
- **3D表示の初回描画(setMesh)は重くなる可能性があります**。特に大きいモデルを
  読み込んだ直後は、画面が一瞬固まったように見えることがあります。
- **FPS(描画のなめらかさ)は未実測です**。大規模モデルでの描画性能の実測・
  最適化は今回のスコープ外です。「もたつく」と感じた場合はどの操作・
  どのモデルサイズだったかをメモしておいてください。
- **タッチ操作(スマホ・タブレットの指操作)には対応していません**。マウスでの
  操作を前提にしています。
- **レイヤー情報を持たないモデルでは、レイヤータブが0件のまま無効化され、
  押せません**(フォールバック挙動。不具合ではありません)。
- **ファイル選択・保存ダイアログは、サーバを起動したフォルダの外を見ることが
  できません**(仕様です。「2. 対象ファイルについて」を参照してください)。
- **共有形状化(consolidate)は既定でOFFです**。出力欄のチェックボックスで
  明示的にONにしない限り、重複形状は個別のまま出力されます。
- 「省メモリ方式で書き出す」チェックボックスも既定OFFです(既定は一括GC)。
  操作パターンには保存されません(consolidate 側と同じ扱い)。

## 6. トラブル時の対処

- **ポートが使用中でサーバが起動しない**: 上記「1. 起動方法 > ポートが
  使用中の場合」を参照してください。
- **画面が古い表示のまま/操作しても反応が変わらない**: ブラウザで
  `Ctrl+F5`(強制再読込)を試してください。キャッシュされた古い画面が
  表示されている可能性があります。

## 7. CUI版(コマンドライン対話ツール、大規模IFC向け)

GUI版(上記1〜6章)は3D表示を伴うため、数百MB〜数GB級のIFC(鉄骨ファブ由来で
要素数は少なくても1要素あたりの形状が非常に重いモデル等)では画面が固まったり
メモリを使い切ったりすることがあります。CUI版は3D表示を行わず、クラス名単位で
削除・軽量化を決め打ちする、大規模ファイル向けのコマンドライン版です。

### 7.1 起動方法

GUI版と違い、CUI用のダブルクリック起動用の `.bat` は**意図的に用意していません**
(コマンドライン操作が前提のツールのため)。コマンドプロンプトまたはPowerShellで、
このフォルダに移動してから実行してください。

Python環境がある場合:
```
.venv\Scripts\python.exe -m ifc_occam cui <IFCファイルパス>
```

exe配布版がある場合(`dist\ifc_occam\ifc_occam.exe` が存在する場合):
```
dist\ifc_occam\ifc_occam.exe cui <IFCファイルパス>
```

exe配布版は `ifc_occam.exe` 1つでGUI・CUI・診断の3役を兼ねます。**無引数
(`start-exe.bat` のダブルクリックを含む)ならGUI(serve)が起動します。**
`cui`/`diagnose` のサブコマンドを付けて実行すると、そのサブコマンドが
そのまま動きます。診断レポート(クラス別ランキング・重複形状群など、
3D表示や対話なしで確認できる版)が欲しいだけの場合は次でも起動できます:
```
dist\ifc_occam\ifc_occam.exe diagnose <IFCファイルパス>
```

オプション:
- `--output <出力パス>`: 出力ファイル名を先に固定する(指定時は対話中の
  ファイル名確認プロンプトが出ません)。
- `--scan-only`: 軽量スキャンとランキング表示だけを行い、対話に入らず終了する
  (パイプでの自動処理・大規模ファイルの下見に便利)。
- `--text`: 操作が delete のみのとき、テキストモード(フルオープン不要)への
  切り替えを提案する(後述の「テキストモード」の注意点も参照)。
- `--inline-cleanup`: 省メモリ方式で書き出す(逐次ゴミ回収)。GUIの
  「省メモリ方式で書き出す(逐次ゴミ回収)」チェックボックスと同じもので、
  既定の書き出し時一括ゴミ回収(GC)が使う大きな一時メモリを避けたいときに
  使う。テキストモードでは効果なし(そもそもフルオープンしない)。

### 7.2 対話コマンド一覧

```
delete <クラス名>                       クラス全要素を削除対象に追加する
bbox <クラス名> [element|shared]         クラス全要素をbbox軽量化対象に追加する(既定: shared)
hull <クラス名> [element|shared]         クラス全要素を凸包化対象に追加する(既定: shared)
decimate <クラス名> <ratio> [element|shared]  クラス全要素を間引き対象に追加する(ratio: 0.05-0.95、既定: shared)
keep <クラス名>                         操作指定を解除し、保持対象として明示する
undo [番号]                            操作リストから1件取り消す(番号省略時は直前の1件)
list                                   現在の操作リストを表示する
rank                                   診断ランキングを再表示する
apply                                  操作リストをIFCファイルに適用して出力する(確認2回)
quit                                   対話を中断して終了する(ファイルは変更されない)
h / help                               このヘルプを表示する
```

クラス名は大文字・小文字を区別しません(`delete ifcwall` でも
`delete IFCWALL` と同じに解釈されます)。前方一致しない入力をすると、
前方一致する既知クラスの候補が表示されます。

**bbox/hull/decimate(簡略化系)は既定で「共有波及」(scope=shared)です。**
IFCは同じ形状定義(ジオメトリ)を複数の要素で共有できるため、指定したクラスの
要素を簡略化すると、同じ形状を使う別クラスの要素の見た目もまとめて変わります
(GUI版の「共有波及」オプションと同じ挙動です)。例えば配管系のモデルで

```
> decimate IfcPipeFitting 0.1
```

と指定すると、`IfcPipeFitting` の要素だけでなく、同じ形状定義を共有する
継手・直管以外のクラスの要素の形状も一緒に間引かれます。個別の要素だけに
効かせたい場合は、コマンド末尾に `element` を付けてください
(`decimate IfcPipeFitting 0.1 element`)。既定の `shared` を明示的に書いても
かまいません(`decimate IfcPipeFitting 0.1 shared`)。

この波及がどこまで及ぶかは、`apply` の確認2(実ファイルで確認済みの内容)で
開示されます。操作で指定していないクラスの要素にも波及する場合は

```
共有波及: 操作で指定していない 42要素 の形状も対象になります(IfcPipeSegment: 30, IfcValve: 12)。
```

のような行が追加表示されます(波及先が無ければこの行は出ません)。内容を
確認してから実行するかどうかを判断してください。

注意点が2つあります。1つ目: 「対象になります」という表現は「必ず形状が変わる」
ことの保証ではありません。共有先の要素の配置変換(`MappingTarget`)が非一様
スケール等で安全に逆変換できない場合、その要素だけ個別化(`element`相当)に
フォールバックし、共有マップ自体は変更されません(この場合はフォールバックの
警告が別途表示されます)。2つ目: `IfcMappedItem` を介さない直接共有(複数要素が `IfcMappedItem` を経由せず
同一の `IfcShapeRepresentation` を直接参照する構成。実データでは稀)も、
2026-08-01 からこの開示の集計対象です。同じ形状への複数操作は共有マップと
同様に先勝ちになり、無視された操作は警告で表示されます。

### 7.4 大規模ファイルを扱うときの注意

CUIは「軽量スキャン(ファイル全体を読むがifcopenshellは使わない)」と
「フルオープン(`apply`実行時に1回だけ、ifcopenshellでファイル全体を
メモリに展開する)」の2段構えです。Task 8(2026-07-25)で鉄骨ファブ系の
実データ3種(292MB/1.2GB/6.5GB)を実測した結果、時間・メモリの目安として
以下が分かっています(詳細な実測条件は非公開の内部記録にあります)。

- **スキャン**: ファイルサイズにおおよそ比例(実測15.3MB/s、6.5GBで約7.6分)。
- **推定フルオープンメモリ**: `rank`の出力に「推定フルオープンメモリ: nnn
  bytes」として、ファイルサイズの概算14倍が表示されます(実測で
  292MB/1.2GBファイルのフルオープン単体ピークがファイルサイズの約13〜14倍
  だったことに基づく係数。旧係数は7倍だったが実測に基づき校正した)。
  この推定値がある閾値(ファイルサイズ換算で2GiB相当)を超えると、`apply`
  実行時に「警告: 推定フルオープンメモリが大きく...」という警告が出ます
  (続行するかどうかは自己責任で判断してください)。実測ではフルオープン
  単体で1.2GBファイルが約14.75GiB(32GiB搭載機の約46%)のメモリを使いました。
- **削除は「要素数」だけでなく「1要素あたりの形状の重さ」に強く依存します**。
  実測(292MBファイル、たった456要素の削除)では**削除に約2.78時間
  (10,024秒)** かかりました。これは要素1件あたりの推定Face数が約4,600と
  非常に多かったためです(以前の実測large.ifc・軽量な要素での削除は
  1件あたり0.1〜0.14秒程度)。**「要素数が少ないから早く終わる」とは
  限りません**。`rank`の「推定Face数(展開)」列が大きいクラスは、要素数が
  少なくても削除に時間がかかる可能性を考慮してください。
- **6.5GB級のファイル**: Phase 1ではフルオープン(`apply`)は現実的な時間・
  メモリで完走しない規模です(推定フルオープンメモリが数十GBに達し、警告が
  出ます)。`--scan-only`で軽量スキャンとランキングだけを確認する使い方を
  推奨します。`apply`しようとすると警告が出ますが、フルオープン自体は警告
  確認(確認1)で`n`と答えれば実行されません。
- **テキストモード(`--text`、テキストレベル削除)にも別のメモリ上限があります。**
  `scan_full_graph`(参照グラフスキャン)はファイルサイズの約1.6倍のメモリを
  使います(中間配列の削減後に1.2GBで実測1.63倍。参照密度が上がると係数も
  上がります。以前は約4.79倍)。6.5GBのファイルでは投影で約11GB(1.2GBの
  実測係数からの換算)、32GB搭載機での全要素削除の完走を実測済みです
  (27.4分。検証モデルは関係レコードをほぼ含まない単一クラス構成のため、
  関係レコードの多い実務モデルでは計画段の処理が増えます)。この係数は
  Pythonロジックそのままなので、exe化しても変わりません。
- **フルオープン経路の書き出し時メモリやディスクが厳しいとき**は
  `--inline-cleanup`(またはGUIの「省メモリ方式で書き出す」)を試してください。
  既定の書き出し時一括ゴミ回収は一時的に使うメモリ(モデルサイズの数倍)に
  加えて、出力先の隣にほぼ出力サイズの一時ファイルをディスクに使います。
  `--inline-cleanup` はこれを避け、簡略化のたびに古い形状を逐次回収します。
  生き残る要素と幾何は既定方式と同一で、同じ入力・同じ操作であれば出力は
  一括GCと完全に一致します(consolidate OFF=既定の場合。ONだと共有先の
  代表選択が非決定的なため等価だがバイト一致はしない)。以前は旧形状の
  回収が一括GCほど徹底せず出力が数%大きくなることがありましたが、この差は
  解消済みです。逐次回収のぶん掃除は一括GCより遅くなることがあります。
- **`quit`で安全に中断できます**。フルオープン前(確認1の時点)で`n`と答えるか
  `quit`すれば、原本ファイルは一切変更されません。
- **進捗表示**: 削除・簡略化の進捗は同じ行を上書き表示します(`\r`)。
  ターミナルによっては複数行に見えることがありますが、処理自体は
  正常に進行しています(表示上の見え方の違いです)。**進行中は次の
  節目(500件ごと、または完了時)まで表示が変わらないことがあります**
  (先着1件目・以後500件ごと・完了時のみ更新する仕様のため)。
- **鉄骨ファブ系データの特徴(実測の所見)**: 実測した3ファイルは
  いずれも要素の100%が`IFCBUILDINGELEMENTPROXY`という単一クラスに
  分類され、`rank`のランキングは「1行・寄与率100%」にしかなりませんでした。
  このようなデータでは、クラス名だけでは削除/保持の判断材料になりません。
  `IFCBUILDINGELEMENTPROXY`のName属性(例:
  「【曲折円柱】曲折円柱 (1903)」のように末尾に個体連番が付くことが多い)を
  見て、先頭の【カテゴリ名】タグで判断する必要があります。現行のCUIは
  この「タグ単位の集計」を画面に表示しないため、クラス名も個体名(連番)も
  判断材料にならないデータでは、`rank`だけでは十分な決め手が得られない
  可能性があります。

## 8. 開発者向け: オフスクリーン描画で色を確認する

このセクションは、3Dビューの描画(マテリアル・シェーディング・ライト等)を
変更する開発者向けです。GUI版の見た目を実際に確認する手段として使います。

### 背景

自動検証用のブラウザペインなど一部の環境では、ブラウザタブが hidden 判定に
なり `requestAnimationFrame` が止まるため、**スクリーンショットも3Dビューへの
クリック操作も効きません**。見た目を確認する手段が無いと、描画結果が壊れて
いても(例: 法線属性が無いままスムーズシェーディングを使い、モデル全体が
真っ黒に潰れる)気付けません。

### 使い方

モデル読込後、ブラウザの開発者コンソール(または自動操作スクリプト)から
次を実行してください。

```js
window.__debug.measureRender()
```

現在の3Dビューの `scene` を、本番のレンダラとは別のオフスクリーン
`WebGLRenderer` で1フレームだけ描画し、画素を読み取って統計を返します
(実装は `web/rendercheck.js` の `measureRenderedColors`)。戻り値は次の形です
(small.ifc を読み込んだ状態での実測例)。

```js
{
  coloredPx: 2404,          // 彩度(max-min)が閾値を超えた画素数
  coloredPct: 1.67,         // 全画素に対する割合(%)
  avgLumaOfColored: 132.4,  // 着色画素の平均輝度(0-255)
  darkPct: 7.6,             // 輝度40未満の画素の割合(%)
  totalPx: 144000           // 総画素数(既定 480x300)
}
```

**値は配色モードによって変わります。** 上の例は「クラス別」配色のものです。
出荷時の既定である「IFCの色」では、IFC本来の色がクラス色より暗いため
`avgLumaOfColored` が半分以下になります。small.ifc での実測は次のとおりです。

| 配色モード | coloredPx | coloredPct | avgLumaOfColored | darkPct |
|---|---|---|---|---|
| IFCの色(既定) | 2202 | 1.53 | 58.7 | 7.87 |
| クラス別 | 2404 | 1.67 | 132.4 | 7.6 |

**既定のまま測って `avgLumaOfColored` が 58 前後でも異常ではありません。**
どちらのモードで測ったかを必ず添えて記録してください。

引数で解像度と閾値を変えられます(通常は既定のままで構いません)。

```js
window.__debug.measureRender({ width: 960, height: 600, chromaThreshold: 8 })
```

- `width` / `height`(既定 480 / 300): 計測解像度。`coloredPx` は解像度に
  比例するので、**変更前後を比べるときは同じ値で測ってください**。
- `chromaThreshold`(既定 18): 「着色されている」とみなす彩度(RGBの max-min)の
  下限。無彩色のステージ(床)や背景を数えないための閾値です。淡い色を
  拾いたいときだけ下げてください。

計測用のレンダラは1つだけ作って使い回します(呼ぶたびに新しい `WebGLRenderer` を
作るとブラウザのWebGLコンテキスト上限に当たり、本番の3Dビューのコンテキストまで
奪われて画面が死にます)。何回呼んでも安全です。

### 判定基準

- **モデルが正しく描かれていれば `coloredPx` は 0 より大きい**(クラス色・
  操作ステータス色・選択色のいずれかが画面上に見えている)。
- **モデルが真っ黒に潰れていれば `coloredPx` は 0** になる(彩度のある画素が
  1つも無い)。

### 手順として必須

**3Dビューの描画に関わる変更(マテリアル・ライト・シェーディング・カメラ等)を
加えたときは、必ず `window.__debug.measureRender()` を通してから完了として
ください。** `coloredPx` が 0 のままなら、変更後も画面には何も見えていない
(真っ黒)ことを意味します。

### 配色モードの確認

配色に関わる変更(`resolveBaseColor`/`ifcColorToLinear`/`repaintColors`/
`setMesh` の `colorMode` 引数、減光の下限 `DIM_FLOOR` 等)を加えたときは、
`#color-mode-select` の値を両方(`ifc`/`class`)試したうえで、それぞれ
`measureRender()` を通してください。

```js
const select = document.getElementById('color-mode-select');
select.value = 'class'; // または 'ifc'
select.dispatchEvent(new Event('change', { bubbles: true }));
window.__debug.measureRender()
```

small.ifc を無選択で読み込んだ状態での実測値の目安は次の通りです
(解像度・閾値は既定のまま)。

| 配色モード | coloredPx | avgLumaOfColored |
|---|---|---|
| クラス別(`class`) | 2404 | 132.4 |
| IFCの色(`ifc`、既定) | 2202 | 58.3 |

どちらのモードでも `coloredPx` が 0 より大きいことに加え、モードを切り替えると
数値が変わることも確認してください(変わらない場合、塗り直し自体が起きていない
可能性があります)。
